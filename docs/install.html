Docs / Install

One curl and you're done.

The installer works out your platform, downloads a verified binary, or compiles the one Rust file itself with rustc. It wires the shell function after installing the binary, because sdcfg init generates the wrapper.

install
$curl -fsSL https://raw.githubusercontent.com/noxthedevwindev-greatest/simpledir/v13.0.0/install.sh | bash

Prefer to look before you pipe? That's the right instinct — curl -fsSL … -o install.sh, then less install.sh && bash install.sh.

1

The binary lands in ~/.local/bin

The rc block puts that directory first on PATH, so an unrelated sd elsewhere can't win.

2

The shell function is wired in

eval $(sdcfg init) emits a function, not an alias. Functions work in scripts and eval; aliases don't.

3

The checksum is checked

A wrong checksum is fatal before anything is run. A missing one warns, for old mirrors and offline boxes.

4

You jump

sd dots writes a path to stdout; the function performs the cd in your own shell. A subprocess cannot do it.

Downloading by hand

GitHub strips the executable bit from raw release assets, so sd-linux-x86_64 arrives as 0644. Run chmod +x sd, or take the .tar.gz asset, which keeps 0755 and the sdcfg symlink. install.sh already does all of this for you.

manual install
$ curl -fsSLO https://github.com/noxthedevwindev-greatest/simpledir/releases/download/v13.0.0/simpledir-v13.0.0-linux-x86_64.tar.gz
$ tar -xzf simpledir-v13.0.0-linux-x86_64.tar.gz
$ cd simpledir-v13.0.0-linux-x86_64 && install -m 755 sd ~/.local/bin/sd
$ ln -s sd ~/.local/bin/sdcfg
$ sha256sum -c SHA256SUMS
Uninstall. sdcfg uninstall removes the binaries and the wrapper. With SIMPLEDIR_RC set, both uninstall and doctor touch only that file — never a guessed ~/.bashrc.

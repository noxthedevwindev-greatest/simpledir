Supply chain

The download checks itself.

Until 11.0, both install paths asked one question of a binary fetched over the network: does it claim to be us? That's a question about what the file says. Now every release ships a SHA256SUMS.

verified / refused
==> checksum verified against the published SHA256SUMS
==> got sd 13.0.0 - see it all, tidy it up…

!! CHECKSUM MISMATCH for sd-linux-x86_64
!!   published: 3dac5b53a658…
!!   downloaded: 1c72c1cf950f…
xx does not match the checksum this release published.

Wrong is fatal

The installer, sdcfg update and the PKGBUILD compare against the published sums before anything is run or replaced. A wrong sum stops everything.

Missing only warns

Old mirrors and offline boxes must not brick an install for reasons that have nothing to do with tampering.

Hash it yourself

sd sha256 <file> checks a download without trusting the thing doing the verifying. SHA-256 is forty lines of arithmetic in src/main.rs.

Run what you fetched

The updater runs the download with --version and checks it really is simpledir and really newer before swapping the binary in.

What this does and does not prove. A checksum published next to the file it describes proves the two arrived together. It cannot prove who wrote them — anyone who can change the download can change the sum. Signing releases is the next step up, and this is not it.

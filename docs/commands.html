Command reference

Every verb, in one place.

If you don't know a command, this is the page for you. sd only reads and moves. sdcfg only writes and configures. Every flag is long-form — no short aliases to misremember.

sd — moves you, reads config only
$ sd dots              jump to a name
$ sd dot               a unique prefix
$ sd dots/nix           into a subdir
$ sd -                 previous directory
$ sd                    $HOME
$ sd /some/path          a raw path, cd'd as-is
$ sd ls [query]         list aliases; --names or --json
$ sd print name[/sub]   write the path, don't cd
$ sd top [query]        frecency, best first; --json
$ sd recent [query]     newest visits; --top N, --json
$ sd stats              counts and dead paths; --json
$ sd suggest [query]    mine shell history; --json
$ sd i [query]          interactive picker (fzf)
$ sd adapt [--top N]    unnamed directories you keep visiting
$ sd sha256 file        hash a download yourself
$ sd --help              this text
sdcfg — changes things, never moves you
$ sdcfg add [name] [path]  bind a name; defaults to $PWD
$ sdcfg rm name            unbind; --prune-tags
$ sdcfg rename old new     keep path; --tags carries tags
$ sdcfg import dir         bind every subdirectory
$ sdcfg bind                name what suggest found
$ sdcfg tag @name alias... group aliases
$ sdcfg tag @old --rename @new
$ sdcfg project add|rm     follow you into a project
$ sdcfg adapt [--accept n] accept or reject a suggestion
$ sdcfg export [file]      portable config, $HOME becomes ~
$ sdcfg adopt file         merge a config back in
$ sdcfg forget              drop directories from the log
$ sdcfg tidy [--dry-run]   prune dead aliases, tags, history
$ sdcfg migrate             config file v1/v2 → v3
$ sdcfg zoxide              import zoxide's directories
$ sdcfg edit [editor]      open config in $EDITOR
$ sdcfg init                print the shell wrapper
$ sdcfg prompt bash|zsh    print the prompt segment
$ sdcfg completions bash|zsh
$ sdcfg update | revert | releases
$ sdcfg uninstall | doctor | bench
The split is the point. sd is safe in a pipeline and safe to hit by reflex. sdcfg is a plain executable, so nothing can shadow it. migrate moves the config; update replaces the program. They are unrelated and neither calls the other.

Flags you will actually use

flagmeanswhere
--forceoverwrite an existing aliassdcfg add
--keep-symlinksstore the symlink instead of its targetsdcfg add/import
--dry-runshow the cleanup plan without doing itsdcfg tidy
--yesapply the cleanup without promptingsdcfg tidy
--tagscarry tag membership across a renamesdcfg rename
--prune-tagsdrop the alias from tags when removing itsdcfg rm
--top Nlimit the list to N entriessd top/recent/adapt
--jsonmachine-readable outputsd ls/top/recent/stats/suggest
--purgeremove history as well as the aliassdcfg rm/forget
--runs Nbenchmark iterationssdcfg bench
a typo tells you the fix
$ sd dotfile
sd: no alias named 'dotfile'
  did you mean: dotfiles
  see them all: sd ls
a dead directory tells you the fix
$ sd oldproject
sd: /home/you/Projects/oldproject is gone
  it was bound as oldproject. rebind it:
  sdcfg add oldproject /the/new/place
  or drop it: sdcfg rm oldproject
